# Куда выкладывается игра

Игра — один файл `index.html`. Никакой сборки нет: что лежит в репозитории,
то и открывается в браузере.

## GitHub Pages (сейчас основной)

`.github/workflows/pages.yml`. На каждый push в ветку сперва идёт задача
«Пробники» — весь `tools/check.sh`, — и только если она зелёная,
запускается деплой. **Красный файл на сайт не попадает.** Цена: деплой
занимает 6–7 минут, потому что ждёт прогон.

Адрес: https://dikozi.github.io/boxing-prototype/

## Vercel (превью каждой правки)

Что даёт сверх Pages:

- **свой адрес у каждого push** — правку можно посмотреть, не заменяя
  живой сайт, и сравнить две версии рядом;
- **откат на любой прошлый деплой** одной кнопкой;
- деплой за секунды, а не за семь минут.

Чего НЕ даёт: сам файл не меняется, офлайн-режим и скорость игры те же.
Серверная часть игре не нужна.

### Подключение (делается один раз, в интерфейсе Vercel)

1. vercel.com → Add New → Project → импортировать `dikozi/boxing-prototype`.
2. Framework Preset: **Other**. Build Command и Install Command оставить
   пустыми, Output Directory: `.` — это уже прописано в `vercel.json`.
3. Deploy.

Дальше Vercel сам собирает каждый push. `.vercelignore` оставляет на
сайте только `index.html`.

### Важно про проверки

Vercel деплоит push сразу, не дожидаясь пробников. Поэтому разумно
оставить так: **Pages — боевой адрес под защитой пробников**, Vercel —
превью для «посмотреть глазами». Если хочется наоборот, в Vercel надо
выключить автодеплой (Settings → Git → Ignored Build Step) и дёргать
Deploy Hook из шага `deploy` в `pages.yml` — тогда и там будет та же
защита.
